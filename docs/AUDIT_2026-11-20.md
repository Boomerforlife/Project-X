## 2. Why questions "did not appear"

The data reached the browser. The **links** from the lists did not lead to the question.

1. Public chapter pages list each question with a link. Because every published question is `AI_GENERATED`, the web
   sent them to `/practice/new/?q=<id>`. In API mode the launcher ignores `q` (it only reads `slug`), so a student landed
   on a generic "start practice" screen, never the question they clicked.
2. Signed-out students were redirected to `/login/?next=/practice/new/` — the query string was dropped, so even after
   signing in they lost the question.
3. The single-question path (`startSingleBySlug`, also used by "reattempt" in Bookmarks and the Mistake notebook) fetched
   the question from `GET /public/questions/{slug}`. That endpoint only serves official-key-matched or human-verified
   questions, so it returns 404 for all 433 current questions.
4. The web decided "has a public page" from `origin !== AI_GENERATED`, a rule the API does not use; a future PYQ that is
   only AI-checked would have linked to a 404.

**Fix (no data changes):**
- The API's question summary gains an optional `public_page` flag computed with the same rule as the detail endpoint
  (`packages/contracts/src/dto/public.ts`, `apps/api/src/mappers/question.ts`). The web links to a public page only when
  `public_page === true`, so an older API build (field absent) safely falls back to practice links.
- List links carry `slug`, `exam`, `subject` and `chapter` (`src/components/content/QuestionList.tsx`).
- `startSingleBySlug` falls back to `GET /practice/questions` (which serves every published free question without its
  answer), narrowed to the chapter, when the public page does not exist (`src/lib/session/store.ts`). Works against the
  API that is live today.
- The login redirect keeps the query string (`src/components/app/DemoGate.tsx`).

Verified with real records: the live API returns 15 questions for Kinematics through both the chapter and the practice
endpoints; 433 / 433 published questions have a current solution; 0 have a public page.

Checked and sound (no change needed):
- **RLS and grants (live DB):** RLS on every public table; `anon` can read only active `exams/subjects/chapters/topics`;
  no client grants on questions, solutions, billing, pipeline or audit tables; every `security definer` function pins
  `search_path`. Profile updates are column-limited by grant (`0012`, `0015`).
- **Auth:** JWKS verification with audience + issuer; anonymous sessions rejected on user routes; admin/reviewer roles
  checked server-side; every owner-scoped route filters by the token's user id (sessions, attempts, orders, bookmarks,
  mistakes, rewards, uploads, plans).
- **Payments:** webhook HMAC checked before parsing; events deduplicated by id; order rows locked; amount and currency
  re-checked; checkout verify requires a valid signature **and** Razorpay's own record showing `captured`; refunds revoke
  only on full refund; expiry is computed at request time from `billing_entitlements`, so lapsed passes lose access
  automatically. The client never decides tier: `/entitlements` and `/billing/me` come from the database.
- **CORS:** allow-list, no credentials. **Errors:** generic 500s, DB messages logged server-side only.
- **No SSRF:** no endpoint fetches a client-supplied URL. `/api/dev/token` is 404 in production; `/api/revalidate`
  requires a ≥ 32-character secret, compared in constant time.

## 4. UX fixes

- Question links now open the question (see §2), including after sign-in.
- Hydration error (React #418) on `/pricing/`: `useAuthStatus` returned live state during hydration. It now reports
  `loading` until hydrated (`src/lib/session/store.ts`).

  (`NOT_FOUND_METADATA` in `src/lib/seo.ts`).
- Landing page: no longer promises CBT papers or links to empty "coming soon" pages while papers are hidden; exams with
  no chapters say "Coming soon" instead of "0 chapters →"; the primary CTA says "Start practising free" in production.
- Bookmarks / Mistake notebook "reattempt" works for AI-checked questions again.

## 5. Plus positioning and pricing (Phase 8)

- New `--plus` accent token (rose; 7.5:1 dark, 5.5:1 light) so Premium no longer borrows the orange "marked for review"
  colour. One shared mark, `PlusBadge`, used in the header, pricing, study plan and problem library.
- `/pricing/`: a clean Free card beside an elevated Plus card with a pass picker (30 days / 90 days / 1 year, per-month
  price and "Save N%" computed from server prices), a "What Plus adds" list and one Plus-coloured call to action.
  Passes are named by length, not "Monthly/Quarterly", because they do not renew.
- Side-by-side comparison table (`PlanCompare`) generated by `src/lib/billing/compare.ts`: free-tier numbers come from
  `GET /entitlements` and `GET /billing/plans`; rows for features hidden in this build (papers/CBT, ads) or not backed
  by content (solution extras: 0 of 433 solutions have them) are left out. Unit-tested.
- Benefits listed today (all enforced by the API and verified against live data): every version of each library problem
  (free: 3; 53 of 94 problems have more), study plans up to 14 days / 120 min (free: 7 days / 60 min), the full
  chapter-by-chapter diagnostic report. Full papers / CBT reappear automatically when the papers flag is on.
- Header: "Free · Get Plus" for free users while payments are on; Plus users see the Plus badge. Dashboard prompt copy no
  longer mentions CBT unless papers are on. Prices and entitlements were **not** changed.
